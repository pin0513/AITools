# 訂單取消與退款 (PM spec)

## 1 背景與目標
目前顧客要取消訂單必須打電話給客服。目標:顧客自助取消,並由系統經付款閘道自動退款。

## 2 使用者與情境
顧客:想快速取消訂單。客服人員:需要查看取消紀錄。系統:負責退款。

## 3 功能需求
### 3.1 顧客可在出貨前取消訂單
顧客可以在訂單狀態為已下單時取消訂單。訂單一旦已出貨就不可取消。取消後訂單狀態改為已取消。

### 3.2 取消後系統經付款閘道退款
訂單已取消後,系統透過付款閘道退款。付款閘道失敗時系統最多重試 3 次,訂單維持已取消。退款成功後訂單狀態改為已退款。

### 3.3 客服人員可查看取消紀錄
客服人員可以查看每筆訂單的取消紀錄,包含時間與原因。

## 4 非功能需求
95% 的訂單在取消後 5 分鐘內完成退款。

## 5 驗收條件
- 訂單狀態為已下單 → 顧客取消訂單 → 訂單狀態為已取消
- 訂單狀態為已出貨 → 顧客取消訂單 → 回應 409 ORDER_SHIPPED,狀態不變
- 訂單已取消且已付款 → 系統退款 → 呼叫付款閘道,訂單狀態為已退款
- 付款閘道逾時 → 系統退款 → 重試 3 次,訂單維持已取消
- 有訂單已取消 → 客服人員開啟紀錄 → 每列顯示訂單、時間與原因
